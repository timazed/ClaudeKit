# Experiment evidence

Captured 14–15 October 2026 from the demo itself and Xcode. The physical device was an iPhone 16 Pro Max running iOS 27.0.1. The simulator ran iOS 18.6. The initial tests used a local model fixture. On 15 October, the user completed the official Claude-account browser login and a real model turn on the iPhone.

Account-login correction: [desktop-auth-init.json](desktop-auth-init.json) verifies that the unmodified harness initiates its own Claude-account OAuth flow, including PKCE and a localhost callback, with no API key. [iphone-auth-init.json](iphone-auth-init.json) records the same initialization on the physical phone. [ui-tests-account-summary.json](ui-tests-account-summary.json) records three passing UI tests, including official-account login initiation plus the existing tool/permission tests. Auth initiation alone is separate from the subsequent live result below. Authorization URLs, state values, and authorization codes are deliberately absent from the exported evidence.

[ui-tests-browser-summary.json](ui-tests-browser-summary.json) separately verifies that Continue in browser presents the system Safari sheet, Done dismisses it, and the app remains available to continue sign-in. The account-login build was subsequently installed and exercised on the physical iPhone.

- [iphone-account-tool-loop.json](iphone-account-tool-loop.json): real Claude-account turn, retrieved on 15 October. Claude Sonnet 4.6 returned success after 3 model turns, 1 Swift write, 1 Swift read, 2 manual approvals, and 124 stream events. Fixture model requests were zero; the harness reported no API-key source. Both runtimes reported process 9780. A persisted official transcript was present. The initialization account snapshot precedes browser sign-in, so its lack of an account is expected. Response text is omitted; the note is represented by a SHA-256 hash.
- [iphone-account-resume.json](iphone-account-resume.json): login restored without browser interaction and session `b5b87514-080f-4694-bb90-d46a39f4b3fd` resumed in a new process (9955). The real model recalled the exact prior note and emitted a fresh marker in 32 stream events, with zero native tool calls or fixture requests. The note was not included in the new prompt. Account metadata is reduced to credential-source fields and a boolean indicating an account was present; no email or tokens are exported. [ui-tests-iphone-account-summary.json](ui-tests-iphone-account-summary.json) records the passing physical-device UI test.
- [desktop-relocated-resume.json](desktop-relocated-resume.json): the official harness resumed the same session after deliberately moving the fixture's container directory; no tools were repeated. This covers the iOS update issue where project lookup by the old absolute working directory failed. The host now uses the harness's existing JSONL-path resume interface.

- [iphone-tool-loop.json](iphone-tool-loop.json): successful physical-device proof. `nativePID` equals `runtime.pid` (4674), `platform` is `ios`, `jitless` is true, and the CLI SHA-256 matches the unmodified npm bundle. There are 3 fixture requests, 2 permissions, 1 write, 1 read, and 28 streamed events. The official transcript exists. The raw protocol/native event log is [iphone-tool-loop.jsonl](iphone-tool-loop.jsonl).
- [iphone-resume.json](iphone-resume.json): app restarted into process 4684 and resumed session `e6a1966f-d60e-4849-a2b6-2883210e9dd6`. The fixture verified the original tool results in the model request, with zero new tool calls. See [iphone-resume.jsonl](iphone-resume.jsonl).
- [ui-tests-summary.json](ui-tests-summary.json): final Xcode UI run, 2 tests passed, 0 failed. The full result bundle is `/tmp/claude-ios-demo/ui-tests-final.xcresult` on the development Mac.
- [simulator-tool-loop.json](simulator-tool-loop.json) and [simulator-resume.json](simulator-resume.json): manual SwiftUI approvals and subsequent resume from that UI test run.
- [simulator-permission-denied.json](simulator-permission-denied.json): deliberately unsuccessful fixture run after tapping Deny. Zero native writes and reads is the expected result; the UI test for this case passed.
- [stock-node-device-failure.json](stock-node-device-failure.json) and [stock-node-simulator-failure.json](stock-node-simulator-failure.json): stock NodeMobile 18.20.4 could not parse a Unicode property regex. Replacing it with the ICU-enabled 18.19.1 build resolved that failure without editing the harness.
- [cache-path-device-failure.json](cache-path-device-failure.json): first ICU-enabled device run completed the tool loop but subsequently failed a delayed cache-directory write. Setting XDG cache paths to `Library/Caches` fixed the failure. The successful device evidence above was checked after that delayed write.
- [demo-source-sha256.json](demo-source-sha256.json): checksum inventory of the delivered host, adapter, fixture, script, and test sources. Third-party archive hashes are in [../ThirdParty/README.md](../ThirdParty/README.md).

Fixture reports preserve the official harness's result and usage object verbatim; their token/cost numbers are synthetic and were not billed. Live evidence omits conversation text and personal account metadata. Live usage/cost fields are the harness's reported metrics, not proof of a charge outside the user's subscription. These tests establish the restricted tool loop, real account inference, and the tested persistence paths; they do not establish full Claude Code feature parity, App Store approval, or redistribution rights.
